Backend API Requirements

Prepared for the Backend Engineering Team

v1.0 · DRAFT
📅 May 2026 🔢 7 Sections · 27 APIs 📱 Mobile App (iOS & Android) ⚡ Endpoints to be defined by backend
Note to backend team: Endpoint URLs and HTTP methods are to be decided by the backend team. This document describes what each API should do, the expected request inputs, and response shape. Please confirm endpoints and share OpenAPI / Swagger spec once defined.
1
Authentication
Phone OTP flow · Token lifecycle
#What it doesRequest bodyResponse
1.1AUTH
Send OTP to phone number		{ phoneNumber }{ success, message }
1.2AUTH
Verify OTP & issue tokens		{ phoneNumber, otp }{ accessToken, refreshToken, tokenType, expiresIn, userId }
1.3AUTH
Resend OTP		{ phoneNumber }{ success, message }
1.4AUTH
Logout & invalidate session		—{ success }
1.5AUTH
Refresh access token		{ refreshToken }{ accessToken, refreshToken, tokenType, expiresIn }
OTP is 6-digit numeric. Expect rate limiting (429) on repeated requests. Tokens must include expiry time so the app can proactively refresh.

✦
Standard API Contract

All responses follow this envelope. Every authenticated endpoint requires the Authorization header.

// Success { "data": { ... }, "success": true } // Error { "error": { "message": "...", "code": "..." }, "success": false } // HTTP status codes 200 OK | 400 Bad Request | 401 Unauthorized | 403 Forbidden 404 Not Found | 422 Validation Error | 429 Rate Limited | 500 Server Error

Custom headers sent by the app on every request:

Authorization
<tokenType> <accessToken>
Village-App-Version
Village (v1.0.0)
Village-Client
iOS | Android | Web
Village-Client-Device
Device name & OS version
Village-User-Id
Authenticated user ID (or "null")
Content-Type
application/json
